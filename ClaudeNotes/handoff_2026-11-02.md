## Loader behavior (from SDFBuilder.cpp / .h)
- `loadSerialized` starts at line index 1: **the first line is never parsed**. The root is the
  builder's own object, so `color` on the root line does nothing. If a file omits the `SDFObject`
  line, its first real line is silently lost.
- Parameter loop: `while (ss.peek() != EOF) { ss >> param; if (...) ss >> value; }`. No errors
  are ever reported.
  - Unknown parameter name: skipped; its value is then read as a "name" and skipped too.
  - Too few values / non-numeric value: failbit. The failing component becomes 0, later
    components of that vector keep their defaults, and the rest of the line is dropped.
  - Too many values: extras are read as names and ignored.
  - Float into an int field (`axis 1.0`): reads 1, `.0` ignored.
  - Bool not exactly 0/1: failbit, rest of line dropped.
  - Negative into `size_t` (`repetitions`, `numPoints`): wraps to a huge value. Crash/hang risk.
  - Out-of-range enum ints (`axis`, `operation`, `colorMode`): `static_cast` unchecked.
  - Commas become spaces; indentation and trailing whitespace are fine.
  - Zero vector for `SDFPlane normal` or `OPRotate axis`: `getNormal()` returns (0,0,0) silently.
- `stepBack()` defaults to 1 step (confirmed in header).
- **Crash:** `pushSDFObj` does `dynamic_cast<CombinationOperation*>(m_lastOp)->setCombineObject(...)`
  unchecked. A shape whose most recent `operate()` was not a combination dereferences null
  (e.g. `COMBAdd` / `OPTranslate` / `SDFSphere`, or a shape with no combination at all).
- **Silent replacement / use-after-free:** `m_lastOp` is not reset after a shape, so a second
  shape without its own `COMB*` (including after a `stepBack`) replaces the first shape in the
  same combination. The old object is destroyed while its pointer may still be in `m_objChain`.
- **Likely dangling root:** the constructor pushes the old base object; `loadSerialized` replaces
  `m_baseObject` without clearing `m_objChain`, leaving `[dangling, newRoot]`. One extra root-level
  `stepBack` pops the real root, and any later stack line uses a dangling pointer. Jack's file ends
  with such a `stepBack`, but only lights follow, so it survives. **Confirm by checking the caller
  of `loadSerialized` (is the builder freshly constructed?).**
- Animations: `animate` binds to the top of the stack if the last added thing was a shape
  (`m_lastAddedObj`), else to `m_lastOp`. `stepBack` and `LightSource` don't change those flags, so
  an animation after `stepBack` binds to the PARENT, and after a light it binds to whatever came
  before the light. Animations between a `COMB*` and its shape bind to the combination (safe).

## Validator rules so far
- Line 1 exactly `SDFObject`.
- Every other non-blank line is a known keyword or a `//` comment; flag near-miss keywords.
- Valid parameter names per keyword, exact value counts, numeric values, no duplicates.
- Int fields integers; `axis`/`operation` 0-2, `colorMode` 0-3; bools 0/1; `repetitions`,
  `numPoints` >= 1; no zero-length `normal` or rotation `axis`.
- A shape must be preceded by a `COMB*` line (only `AN*`/comments/blanks in between); a `COMB*`
  is followed by exactly one shape.
- `AN*` must follow a shape, `OP*`, `COMB*` or `AN*` line; not `stepBack`, `LightSource` or the root.
- Track depth; a `stepBack` that closes the root is allowed only if nothing but `LightSource`,
  `end` or comments follows.
- Subtract/Intersect/Exclude need something already present.
- At least one `LightSource`.

## Math bugs found (Vec2.cpp / Vec3.cpp)
- `Vec3::operator/=(const Vec3&)`: `x = ... : p.x` (assigns divisor). So `v /= 2.0` sets x = 2.
- `Vec3::operator/=(double)`: inconsistent with `/` (divides by 1 when d == 0; `/` returns zero).
- `Vec2::operator/=(const Vec2&)` and `Vec2::operator/=(double)`: y assigned divisor.
- `Vec2::cross` returns `Vec2`; should return `double`.
- `Vec3::floor()` returns the fractional part (GLSL `fract`); rename or check callers.
- Find usages of `/=` to see impact (C++ backend only; possible source of backend differences).
- Review notes: make `Vec3::operator bool` explicit; delete user-written `Vec3::operator=` (rule of
  zero, trivially copyable); default `operator==`; fix const correctness; `#pragma once` in .cpp
  files; `level <= 0` on `size_t`.
