PART 1 - TUTORIAL
================================================================================

A scene is built via a collection of objects, operations, and animations.
Objects are added to the scene with combination operations, and manipulated
with various transform, domain, and resurface operations. The parameters of
scene objects and operations can be altered over time via animations that bind
to those parameters.

The scene automatically has a camera at position x=0.0, y=1.8, z=-5.0 and
pointing directly forward along the z axis (+z). The units should be
considered to be in meters. This gives a decent approximation of a human
point-of-view with a ground plane at the origin, though the user can move the
camera freely while the scene runs. There is no object collision.

The scene will be drawn to a maximum distance of 100 meters from the current
camera position. The camera viewport is dynamic based on the size of your
terminal window and the dimensions of your current font. In most cases the
horizontal field of view in a default terminal window should be approximately
90 degrees.

Each scene should have a base SDFObject, one or more shapes, any number of
operations, any number of animations, and one or more light sources. The scene
builder will add a base object to your scene on loading a .scn file regardless
of whether or not you declared one, but failing to do so on the first line may
result in unintended results, including the possible failure to load the file.
All keywords are case sensitive. If you wish to add comments, it is
recommended that you use the standard double-slash (//) at the start of a line
for clarity, but since any line that doesn't start with a valid keyword will be
ignored, you can technically use nearly any choice of denotation for a comment
line.

Here is an example of a very simple .scn file:

SDFObject
	COMBAdd
	SDFSphere
LightSource

The first line acknowledges that we have an SDFObject at the root of our scene
tree. More on empty SDFObjects later. The second line says we want to add an
SDF object to our scene next. The following line says we want that object to
be an SDFSphere. The final line declares a light source for the scene.

When you load this scene you will see a white sphere lit by a single white
light. You do not technically have to define a light source, but neglecting to
do so will result in incorrect rendering. In fact you can load an empty scene
file but naturally you will be rewarded with an empty scene.

Next we will add an operation to our scene to manipulate the sphere's
position. A raymarching scene operates in a stack pattern. When we add an
object to the stack it inherits all operations beneath it in the stack (there
are some exceptions to this we will mention later). Therefore in order to
operate on our sphere we must add the operation before the sphere is added.

SDFObject
	OPTranslate
	COMBAdd
	SDFSphere
LightSource

Loading this .scn file will produce much the same results as the previous
version but the sphere will appear slightly higher than before. That's useful,
but it is more useful to be able to move the sphere in more directions than
just up. We can do this by adding the "translation" parameter to the
OPTranslate line followed by values for the translation.

SDFObject
	OPTranslate translation 2.0 2.0 1.0
	COMBAdd
	SDFSphere
LightSource

Load the file to see the sphere has been moved up higher than before, and has
also been moved to the right and is further from the viewpoint. Note that the
loader does not require you to explicitly use floating point number formats
for floating point values so the following .scn file works just as well.

SDFObject
	OPTranslate translation 2 2 1
	COMBAdd
	SDFSphere
LightSource

Let's add another object to our scene. There are several objects you can add
and you can find specifications for each object as well as operations and
animations in Part 2 of this document. Notice that a combination is always
followed by an SDF object of some kind. This is, after all, the point of a
combination - to combine objects within the scene in various ways.

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFSphere
		COMBAdd
		SDFBox
LightSource

Load this .scn file to see a cube added to the scene. But where did our sphere
go? Here we can see the effects of using operations in a stack. The translate
operation was added before both the sphere AND the box were added and it
therefore applies to both of them. You may have guessed that the box would
have been added in the default position and the sphere would appear directly
above it as the translate operation moved it up 1 unit, but both objects are
in fact moved up together as one, so the box is directly overlapping the
sphere and hiding it. We can fix this by using the stepBack keyword to move
back down the stack:

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFSphere
		stepBack
	COMBAdd
	SDFBox
LightSource

Running this produces the same result. Understand that every time we add an
object to the scene we add it to the stack. The original object is at the base
level, we then added a sphere, and next a box. Note the indentation used to
illustrate this. Indentation is not required to create a valid .scn file but it
is very useful to keep track of where you are in the stack while defining it.
Note that stepBack is used at stack level 3 (SDFObject is level 0) and the
translate operation was declared at level 1. So we need to stepBack further in
order to pop the translate operation off the stack.

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFSphere
		stepBack
	stepBack
COMBAdd
SDFBox
LightSource

This also doesn't work. The reason is that we have now stepped back to the
same level as our base object. This is not allowed as everything in the scene
must stem from one place and that place is the root SDFObject. The way to
solve this is to always use empty SDFObjects as levels to stepBack onto when
you want to move objects or groups of objects around independently (without
inheriting previous operations). Let's try this .scn file.

SDFObject
	COMBAdd
	SDFObject
		OPTranslate translation 0 1 0
		COMBAdd
		SDFSphere
			stepBack
		stepBack
	COMBAdd
	SDFObject
		COMBAdd
		SDFBox
LightSource

Finally, loading this .scn file will give us a box at the bottom with our
sphere perched on top! Note that the add operation for the SDFBox still
happens at the same level as the translate operation, but since we moved back
down the stack below the level of the operation, it is gone from the stack and
no longer applies. It may seem excessive or feel inconvenient to add an extra
empty SDFObject each time we add a visible object but we don't have to! There
is another way we can achieve the same result:

SDFObject
	COMBAdd
	SDFBox
		OPTranslate translation 0 1 0
		COMBAdd
		SDFSphere
LightSource

This .scn file shows how order of operations and applying our operations at
the appropriate point in the stack can simplify our approach. Note that
changing the translation parameter will only move the sphere. Run the file to
get the same visual results as the previous example.

Different objects have their own parameters that can adjust their shape and
size. Let's add some parameters to our sphere and box:

SDFObject
	COMBAdd
	SDFBox dimensions 2 1 0.5 color 0 0 1.0
		OPTranslate translation 0 1 0
		COMBAdd
		SDFSphere radius 0.75 color 1.0 0 0
LightSource

Now when we load the scene the box is twice as wide and the sphere is 50%
wider as well. And of course the shapes are now rendered with the defined
colors. There are many types of objects we can render each with their own sets
of parameters. Again, you can find them all listed in Part 2 of this file.

There are other kinds of combinations we can use. For example, let's try a
smooth add operation:

SDFObject
	COMBAdd
	SDFBox dimensions 2 1 0.5 color 0 0 1.0
		OPTranslate translation 0 1 0
		COMBAddSmooth
		SDFSphere radius 0.75 color 1.0 0 0
LightSource

See how our shapes are now physically blended together both with surface and
color smoothing. Let's try a subtraction:

SDFObject
	COMBAdd
	SDFBox dimensions 2 1 0.5 color 0 0 1.0
		OPTranslate translation 0 1 0
		COMBSubtract
		SDFSphere radius 0.75 color 1.0 0 0
LightSource

Now our sphere has disappeared... but it has left an impression where it used
to overlap the box! This is a very useful way to create complex custom shapes.
Next let's look at the intersection combination:

SDFObject
	COMBAdd
	SDFBox dimensions 2 1 0.5 color 0 0 1.0
		OPTranslate translation 0 1 0
		COMBIntersect
		SDFSphere radius 0.75 color 1.0 0 0
LightSource

Now we are left with just the piece where the two shapes overlapped! Again,
very useful for creating more complex and interesting shapes! There are also
smooth versions of the subtract and intersect combinations for you to try.

Let's try rotating an object. We'll use a new object, the torus, for this
example:

SDFObject
	COMBAdd
	SDFTorus radii 1.5 0.25
LightSource

Now let's rotate it with an operation:

SDFObject
	OPRotate axis 0 1 0 rotations 0.125
	COMBAdd
	SDFTorus radii 1.5 0.25
LightSource

Ok, there is our torus... but it's not rotating? Actually, it is rotating, but
it is rotating along the vertical y axis so it just looks like it is not
rotating. There are two ways we can change this - we can change the initial
orientation of the torus or we can change the axis of rotation for our
animation. First, let's reorientate our torus:

SDFObject
	COMBAdd
	SDFTorus radii 1.5 0.25 axis 0
LightSource

Now our torus is orientated along the x axis. Values for the axis parameter
are [0=x, 1=y, 2=z] with 1 (y) being the default value. Parameters will all
default to a predetermined value if you do not provide one (see the Default
column in Part 2), so keep this in mind if things are not working as expected.
Now let's try with the rotation operation again but we will use a different
axis:

SDFObject
	OPRotate axis 0.5 1 .875 rotations 0.125
	COMBAdd
	SDFTorus radii 1.5 0.25
LightSource

Now we have a new orientation for our torus entirely. Note that it is good
practice to use normalized vectors for rotational axes, but this application
will automatically normalize the axis on loading here. Otherwise the excess
magnitude of your vector would affect the number of rotations.

Now let's animate the rotation to add some life to our scene!

SDFObject
	OPRotate axis 0.5 1 .875 rotations 0.125
	ANContinuous1D propName rotations
	COMBAdd
	SDFTorus radii 1.5 0.25
LightSource

The ANContinuous1D animation binds to a single-value property (in this case
the "rotations" property) and then continually adds to it while the scene
runs. Animations always attempt to bind to the previous operation or object
declared and must provide a propName that is valid for the operation or
object. If it fails to do so, it will simply not be added to the scene.
Multiple animations can be applied to the same operation or object, but if
they both bind to the same property then the latter animation will override
the former, meaning the former animation will have no effect while still
performing its calculations, so be sure not to bind to the same property.

Most properties that can be provided upon declaration of an object or
operation can be animated. There are 3 types of animations - continuous,
linear cycle, and smooth cycle - each with a version for 1D, 2D, and 3D. Note
that at this time animations cannot be applied to light sources.

Let's look at an example of applying animations to combination operations and
object parameters. First we'll make a scene without animations:

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFBoxFrame dimensions 2 1 1 edgeThickness 0.25
		OPTranslate translation 0 1 0
		COMBAddSmooth
		SDFSphere radius 0.75
LightSource

Now let's add an animation that adjusts the smoothing factor of the smooth add
operation:

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFBoxFrame dimensions 2 1 1 edgeThickness 0.25
		OPTranslate translation 0 1 0
		COMBAddSmooth
		ANSmoothCycle1D propName smoothing amplitude 0.5 period 4
		SDFSphere radius 0.75
LightSource

The smoothing factor of the combination function will now animate. Here, we
are using a smooth cycle animation function which uses a sine function. Note
that earlier we said that a combination is always followed by an object. In
this case, however, the object does not follow as the very next entry but
rather follows after any animations that apply to the combination itself.
There still must be an object that follows before further operations can be
added, otherwise validation errors will occur.

Now let's animate some properties on our box frame object:

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFBoxFrame dimensions 2 1 1 edgeThickness 0.25
		ANLinearCycle3D propName dimensions amplitude 0.25 0.3 0.35
		ANSmoothCycle1D propName edgeThickness amplitude 0.1 period 2.31
		OPTranslate translation 0 1 0
		COMBAddSmooth
		ANSmoothCycle1D propName smoothing amplitude 0.5 period 4
		SDFSphere radius 0.75
LightSource

Here we see that we can animate multiple properties on an object at the same
time. We also see that we use a 3D animation to animate a 3D property such as
a box frame's dimensions. Each dimension of the property can be animated
independently with the same animation.

Next we will see how we can repeat the same object multiple times in a scene.

SDFObject
	OPRepeat limits 2 0 1
	COMBAdd
	SDFSphere
LightSource

This single repeat operation takes a single sphere object and repeats it
fifteen times. The limits determine how many times on each axis to repeat the
sphere. 0 means no additional repeat, while other numbers mean to repeat the
object that many times in BOTH directions along that axis. It is important to
note that the mathematics involved in domain repetition requires objects being
repeated to be centred and symmetrical, otherwise rendering errors may occur,
though in some cases they may be minor enough to not be noticeable. Your
mileage may vary.

We can also repeat objects in a circle:

SDFObject
	OPRepeatCircle axis 2 repetitions 5
	OPTranslate translation 2.0 0 0
	COMBAdd
	SDFSphere
LightSource

Here we can repeat around whichever axis we please and however many times we
please. If we attempt to repeat a large number of times, the objects will
overlap since they will be wider than the slice they occupy:

SDFObject
	OPRepeatCircle axis 2 repetitions 20
	OPTranslate translation 2.0 0 0
	COMBAdd
	SDFSphere
LightSource

We should also note the use of the translate operation here. The translation
should be purely along the x-axis to work correctly. If we do not first
translate before adding our object, the repetition will happen around the
centre of the sphere meaning we will just be repeating the sphere in its same
position. Since the sphere has rotational symmetry it will come out just
looking like the same sphere. If we use a different object we can see what
happens when we don't translate:

SDFObject
	OPRepeatCircle axis 2 repetitions 3
	COMBAdd
	SDFTorus axis 2
LightSource

If you are keen on spatial operations you may think we wouldn't need to change
the axis on our torus from y to z for this to work, but the repeat operation
actually reorientates the repeated objects to its target axis before the
repeat so this must be taken into account.

There is one operation and one combination that actually operate on the inside
of objects. The results of these operations can only be seen if we follow
these up with subtraction operations to reveal the inside. Note that the
OPOnion operation in this example is one exception to the rule that operations
come before the objects they operate on. The other two examples of this are
OPInsideOut and OPRoundOff. Let's look at the onion operation as an example.

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFObject
		COMBAdd
		SDFSphere
			OPOnion
			stepBack
		stepBack
	OPTranslate translation 0 0 -0.5
	COMBSubtract
	SDFBox dimensions 2 2 1
LightSource

See that our sphere is now hollowed out. We could not have known this without
subtracting a part of the sphere to see inside. We can repeat this operation
multiple times:

SDFObject
	OPTranslate translation 0 1 0
	COMBAdd
	SDFObject
		COMBAdd
		SDFSphere
			OPOnion magnitude 0.25
			OPOnion magnitude 0.1
			stepBack
		stepBack
	OPTranslate translation 0 0 -0.5
	COMBSubtract
	SDFBox dimensions 2 2 1
LightSource

We now get concentric nested spheres. The exclude combination also requires a
subtraction to reveal its interior effects.

Let's switch back to animations. It is useful to have an animation that is
somewhat less consistent. Let's take a look at the linear animations.

SDFObject
	OPTranslate translation 0 1 0
	ANLinearCycle3D propName translation amplitude 1 0.5 0.5 forwardTime 0 2.471 3.14 delayTime1 1 1.2 1.35 backwardTime 3.04 0 2.776 delayTime2 1.34 1.15 0.956
	COMBAdd
	SDFSphere
LightSource

(Each .scn entry must stay on a single line, so long example lines like the
one above are not wrapped.)

There is a lot more going on here with so many parameters. So what does each
do? We are defining 3 cyclical paths our object will move, one for each axis.
Let's just pretend we are only using one axis and just look at the first of
each value, the x axis value. First, the amplitude tells the animation how far
to move the object in each direction. The forwardTime parameter tells the
animation how long it takes the object to move forward along the entire
translation. The delayTime1 parameter tells the animation to hold position for
that length of time once it reaches the forward position. We then do the same
thing in the other direction with the backwardTime and delayTime2 parameters.
If this is not clear, try changing all the y and z parameters to 0 so you can
watch what happens on just the x axis.

SDFObject
	OPTranslate translation 0 1 0
	ANLinearCycle3D propName translation amplitude 1 0 0 forwardTime 0 0 0 delayTime1 1 0 0 backwardTime 3.04 0 0 delayTime2 1.34 0 0
	COMBAdd
	SDFSphere
LightSource

Note that a forwardTime or backwardTime of 0 is valid and this will cause the
object to jump instantly across the whole translation.

There is one combination that has its own timed action without using an
animation. Let's take another look at the add combination.

SDFObject
	COMBAdd onTime 2.0 offTime 0.5
	SDFSphere
		OPTranslate translation 0 1 0
		COMBAdd onTime 1.435 offTime 0.5
		SDFBox
LightSource

These parameters allow us to turn an object on and off according to a
schedule. Note that objects further up the stack will also be turned off, but
those higher objects can also be turned off independently.

Hopefully these lessons will help you to begin building out your own fun
scenes. Part 2 lists all objects, combinations, operations, and animations you
can use to build your scenes, including all their parameters (properties).
Remember that all parameters (with the exception of the propName for
animations) have a default value and do not need to be explicitly defined for
every entry. Parameters can also be listed in any order as long as they are
always followed by the appropriate number of valid values.

2.1  CONVENTIONS USED IN THE REFERENCE
--------------------------------------------------------------------------------

Each entry gives the keyword, a short description, an example line, and a table
of its parameters with their types and default values. A parameter you leave out
of a line takes its default value.

    Type    Meaning
    float   a single number (integers are accepted, eg. 2 or 2.0)
    int     a whole number
    bool    0 = false, 1 = true
    vec2    two numbers, eg. 1.0 0.5
    vec3    three numbers, eg. 1.0 0.5 0.25
    name    the name of another parameter (used by propName)
    varies  float, vec2 or vec3 to match the 1D, 2D or 3D animation variant

Axis values are 0 = x, 1 = y, 2 = z. Colors are r g b with each channel ranging
0.0-1.0. Times are in seconds.


2.2  COMBINATIONS
--------------------------------------------------------------------------------

COMBAdd
    Adds an object to the scene stack. Note that the properties of COMBAdd
    cannot be bound to an animation since they handle their own animations.
    Attempts to bind an animator to them will be ignored.

    eg. COMBAdd onTime 1.0 offTime 0.5 phase 0.5 overwriteColor 0

    Parameter            Type   Default     Description
    onTime               float  1.0         How long to show the object
    offTime              float  0.0         How long to hide the object (0 =
                                            always shown)
    phase                float  0.0         How far into the off/on cycle to
                                            start
    overwriteColor       bool   0           Whether or not to overwrite the
                                            existing object's color with that of
                                            the added object

COMBSubtract
    Subtracts an object's shape from objects on the scene stack.

    eg. COMBSubtract

    No parameters.

COMBIntersect
    Subtracts non-intersecting volumes from the scene stack.

    eg. COMBIntersect

    No parameters.

COMBExclude
    Subtracts intersecting volumes from the scene stack. Combine with a
    subtraction to see the interior effect.

    eg. COMBExclude colorMode 3

    Parameter            Type   Default     Description
    colorMode            int    0           How colors are assigned (see below)

    colorMode values:
        0 = shapes retain their color
        1 = shapes gain color of original
        2 = internal surfaces get added color, outer surfaces retain original
        3 = same as 2 but colors are swapped according to proximity

The following four smooth combinations share these parameters:

    Parameter            Type   Default     Description
    smoothing            float  0.5         Distance to smooth over
    colorBlending        float  1.0         Distance to blend colors over
                                            smoothed sections
    colorShifting        float  0.0         Shifts the color smoothing closer to
                                            one object or the other

COMBAddSmooth
    Add with a smoothed intersection.

    eg. COMBAddSmooth smoothing 0.25 colorBlending 1.0 colorShifting 0.0

    Parameters: the shared smooth parameters above.

COMBSubtractSmooth
    Subtract with smoothed edges.

    eg. COMBSubtractSmooth smoothing 0.25 colorBlending 1.0 colorShifting 0.0

    Parameters: the shared smooth parameters above.

COMBIntersectSmooth
    Intersect with smoothed edges.

    eg. COMBIntersectSmooth smoothing 0.25 colorBlending 1.0 colorShifting 0.0

    Parameters: the shared smooth parameters above.

COMBExcludeSmooth
    Exclude with smoothed edges.

    eg. COMBExcludeSmooth smoothing 0.25 colorBlending 1.0 colorShifting 0.0

    Parameters: the shared smooth parameters above.


2.3  SDF OBJECTS
--------------------------------------------------------------------------------

All SDF objects share this parameter:

    Parameter            Type   Default     Description
    color                vec3   1 1 1       RGB color, each channel ranging
                                            0.0-1.0

SDFObject
    An empty object. Use it to add a layer to the stack without adding or
    subtracting shapes.

    eg. SDFObject color 1 0.5 0.25

    Parameters: color only.

SDFPlane
    A ground plane with a normal vector and an offset. A plane with normal 0 1 0
    and offset 0 should be a natural ground plane for the initial camera
    position.

    eg. SDFPlane color 1 0 0 normal 0 1 0 offset -1.5

    Parameter            Type   Default     Description
    normal               vec3   0 1 0       The up vector of the plane
                                            (automatically normalized)
    offset               float  0.0         Offsets the plane along the normal
                                            vector from the origin point

SDFBox
    A box with 6 sides and 90 degree angles.

    eg. SDFBox color 1 0 0 dimensions 2.5 1.0 2.5

    Parameter            Type   Default     Description
    dimensions           vec3   1 1 1       Edge length of each dimension

SDFBoxFrame
    A box with only its edges rendered, at a given thickness.

    eg. SDFBoxFrame color 1 0 0 edgeThickness 0.1 dimensions 2 2 1.5

    Parameter            Type   Default     Description
    dimensions           vec3   1 1 1       Edge length of each dimension
    edgeThickness        float  0.1         Thickness of the rendered edges

SDFSphere
    A sphere defined by a radius.

    eg. SDFSphere color 0 0.5 1 radius 1.5

    Parameter            Type   Default     Description
    radius               float  0.5         The radius of the sphere

SDFEllipsoid
    An ellipsoid with 3 independent radii.

    eg. SDFEllipsoid color 1 1 1 radii 1.0 0.5 0.25

    Parameter            Type   Default     Description
    radii                vec3   1 0.5 0.25  Individual radii for each axis

SDFCrystal
    A regular octahedron.

    eg. SDFCrystal color 0 0 0.5 edgeLength 1.3

    Parameter            Type   Default     Description
    edgeLength           float  1.0         The length of every edge of the
                                            crystal

SDFCone
    A standard cone pointing up.

    eg. SDFCone color 1 1 1 height 1.0 sweep 0.5

    Parameter            Type   Default     Description
    height               float  1.0         The height of the cone
    sweep                float  0.5         The angle of the cone's sides
                                            (0.0-1.0). 0 produces a line

SDFSolidAngle
    A section of a sphere defined by an angle radiating from the center.

    eg. SDFSolidAngle color 0.4 0.2 1.0 radius 0.55 sweep 0.25

    Parameter            Type   Default     Description
    radius               float  0.5         The radius of the sphere
    sweep                float  0.25        The angle (0.0-1.0)

The following objects (SDFTorus through SDFTaperedCylinder) have an axis
parameter which aligns the object along the selected axis (0=x, 1=y, 2=z). 1 (y)
is the default axis.

SDFTorus
    A donut shape defined by 2 radii, major and minor.

    eg. SDFTorus color 0 0 1 radii 2.5 0.5 axis 0

    Parameter            Type   Default     Description
    radii                vec2   1 0.25      The major and minor radii
    axis                 int    1           The axis that passes through the
                                            hole

SDFTorusSegment
    A donut shape defined by 2 radii, major and minor, limited to a partial
    angle.

    eg. SDFTorusSegment color 0 0 1 radii 2.5 0.5 axis 0 sweep 0.5

    Parameter            Type   Default     Description
    radii                vec2   1 0.25      The major and minor radii
    sweep                float  0.25        The portion of the ring that is
                                            rendered (0.0-1.0)
    axis                 int    1           The axis that passes through the
                                            hole

SDFCapsule
    A classic pill shape.

    eg. SDFCapsule color 1 0 1 radius 0.5 bodyLength 2.0 axis 2

    Parameter            Type   Default     Description
    radius               float  0.5         The radius of the capsule
    bodyLength           float  1.0         The length of the capsule, not
                                            including the rounding (the rounding
                                            adds the radius at both ends)
    axis                 int    1           The axis that the body aligns with

SDFCylinder
    A classic cylinder shape.

    eg. SDFCylinder color 0 1 0 sideLength 1.0 radius 0.25 axis 1

    Parameter            Type   Default     Description
    sideLength           float  1.0         The length of the cylinder
    radius               float  0.5         The radius of the cylinder
    axis                 int    1           The axis that the body aligns with

SDFTaperedCapsule
    A pill shape whose radius decreases/increases along its length.

    eg. SDFTaperedCapsule color 1 1 1 bodyLength 2.5 radii 1.0 0.5 axis 2

    Parameter            Type   Default     Description
    bodyLength           float  1.0         The length of the capsule, not
                                            including the rounded ends
    radii                vec2   0.5 0.25    Individual radii for each end of the
                                            capsule
    axis                 int    1           The axis that the body aligns with

SDFTaperedCylinder
    A cylinder shape whose radius decreases/increases along its length.

    eg. SDFTaperedCylinder color 0.5 0.5 0.5 sideLength 1.5 radii 0.2 0.5 axis 0

    Parameter            Type   Default     Description
    sideLength           float  1.0         The length of the cylinder
    radii                vec2   0.5 0.25    Individual radii for each end of the
                                            cylinder
    axis                 int    1           The axis that the body aligns with

The following SDF objects are 2D shapes that can be made 3D with 3 different
operations: 0 = extrusion, 1 = revolve, 2 = infinite column. Extrusion is the
default operation. In the case of extrusion, the magnitude parameter defines the
height of the extrusion. In the case of revolve, magnitude is the radius of the
ring around which the shape is revolved, and the two revolve parameters can also
be used. They all share these parameters:

    Parameter            Type   Default     Description
    operation            int    0           0 = extrusion, 1 = revolve, 2 =
                                            infinite column
    magnitude            float  1.0         Extrusion: the height of the
                                            extrusion. Revolve: the radius of
                                            the ring around which the shape is
                                            revolved
    revolveRotations     float  0.0         The number of times to rotate the
                                            shape before it is revolved
    revolveRotateOffset  vec2   0 0         The offset of the center of rotation
                                            for the revolveRotations parameter

SDFRhombus
    A 2D rhombus that can be extruded or revolved into a ring.

    eg. SDFRhombus color 1 1 0.5 dimensions 1.0 1.5 operation 0 magnitude 1.0

    Parameter            Type   Default     Description
    dimensions           vec2   1 0.5       Width and length of the rhombus

SDFTriangle

    Parameter            Type   Default     Description

SDFEquilateralTriangle

    Parameter            Type   Default     Description

SDFIsoscelesTriangle

SDFPieSlice

SDFPentagon

SDFStar

2.4  OPERATIONS
--------------------------------------------------------------------------------

OPTranslate
    Moves objects by a vector.

    eg. OPTranslate translation 1 2.4 5.2

    Parameter            Type   Default     Description
    translation          vec3   0 1 0       The vector to move the object by

OPRotate
    Rotates an object around a vector axis. The vector will be automatically
    normalized.

    eg. OPRotate axis 1 0 0 rotations 0.75

    Parameter            Type   Default     Description
    axis                 vec3   0 1 0       The vector to rotate around
    rotations            float  0.5         The number of full rotations (1.0 =
                                            one full rotation)

OPElongate
    Elongates objects along an axis.

    eg. OPElongate axis 1 length 1.0 offset 0.25

    Parameter            Type   Default     Description
    axis                 int    1           The axis (0=x, 1=y, 2=z) to elongate
                                            on
    length               float  1.0         The length of the elongation along
                                            the axis
    offset               float  0.0         A distance along the axis that is
                                            the center of the elongation

OPRepeat
    Repeats the object a certain number of times in each direction along the
    x/y/z axes. Note that non-symmetrical objects may result in artefacting.

    eg. OPRepeat spacing 2 1 1 limits 1 1 0

    Parameter            Type   Default     Description
    spacing              vec3   1 1 1       The size of each repeating cell
    limits               vec3   1 1 1       How many times to repeat the object
                                            in each direction (the default makes
                                            3 x 3 x 3 = 27 copies)

OPRepeatCircle
    Repeats the object in a circular pattern. Use OPTranslate following
    OPRepeatCircle to control the radius of the circle.

    eg. OPRepeatCircle axis 2 repetitions 8

    Parameter            Type   Default     Description
    axis                 int    1           The axis (0=x, 1=y, 2=z) to revolve
                                            around
    repetitions          int    10          The number of times the object will
                                            be repeated

OPMirror
    Mirrors the object over the selected axes. By default it mirrors over just
    the x axis.

    eg. OPMirror mirrorX 1 mirrorY 0 mirrorZ 1

    Parameter            Type   Default     Description
    mirrorX              bool   1           Whether or not to mirror over the x
                                            axis (yz plane)
    mirrorY              bool   0           Whether or not to mirror over the y
                                            axis (xz plane)
    mirrorZ              bool   0           Whether or not to mirror over the z
                                            axis (xy plane)

The final three operations are resurface operations. Unlike other operations,
which come before the objects they operate on are added to the stack, these
operations operate on objects already on the stack.

OPRoundOff
    Rounds-off objects by inflating them. Note that this does not work well with
    subtractions. Use a smooth subtraction if experiencing edges that do not
    round-off.

    eg. OPRoundOff magnitude 0.05

    Parameter            Type   Default     Description
    magnitude            float  0.01        The amount to inflate the objects

OPOnion
    Hollows out an object leaving a shell of defined thickness. Requires a
    subsequent subtraction combination to reveal the inside.

    eg. OPOnion magnitude 0.1

    Parameter            Type   Default     Description
    magnitude            float  0.01        The thickness of the shell

OPInsideOut
    Turns solid space to empty space and vice-versa.

    eg. OPInsideOut

    No parameters.


2.5  ANIMATIONS
--------------------------------------------------------------------------------

There are 3 main types of animations - Continuous, SmoothCycle, and LinearCycle.
Each has a 1D, 2D, and 3D variant. Each must reference a valid property name of
the object or operation it is animating. These property names are the same as
the parameter names for each object and operation. Though in some instances a
mismatch of dimensions might still run, some will not. It is important to use
the animation variant that matches the dimensions of the property you are
animating. Use the propName parameter to reference the property you wish to
animate.

All animations share this parameter:

    Parameter            Type   Default     Description
    propName             name   (none)      Required. The property to animate

In the tables below, each numeric parameter is a float, vec2 or vec3 to match
the 1D, 2D or 3D variant, and its default applies to every component.

ANContinuous1D / ANContinuous2D / ANContinuous3D
    Continuously increases the property value by the amplitude.

    eg. ANContinuous1D propName rotations amplitude 1.0 phase 0.5
        ANContinuous2D propName radii amplitude 0.45 0.22 phase 1.0 1.25
        ANContinuous3D propName translation amplitude 0.25 0.5 0.75 phase 0.0 1.0 2.0

    Parameter            Type   Default     Description
    amplitude            varies 1.0         The amount to increase the property
                                            per second
    phase                varies 0.0         The amount of time into the
                                            animation to start

ANSmoothCycle1D / ANSmoothCycle2D / ANSmoothCycle3D
    Smoothly oscillates the property value with a sine function.

    eg. ANSmoothCycle1D propName rotations period 4.0 amplitude 2.0 phase 0.25
        ANSmoothCycle2D propName radii period 2.0 4.0 amplitude 1.0 2.0 phase 1.75 0.25
        ANSmoothCycle3D propName translation period 2.0 4.0 5.5 amplitude 0.25 1.0 2.0 phase 1.75 0.25 1.25

    Parameter            Type   Default     Description
    period               varies 1.0         The amount of time to complete one
                                            oscillation cycle
    amplitude            varies 1.0         The maximum distance (both positive
                                            and negative) from the starting
                                            value
    phase                varies 0.0         The amount of time into the
                                            animation to start

ANLinearCycle1D / ANLinearCycle2D / ANLinearCycle3D
    Animates the values with constant rates over distinct phases. The animation
    is split into a forward motion, a delay, a return motion, and a second
    delay. Each phase has its own duration. The cycle time is the sum of all
    four phases. A phase time of 0 means the object will instantly snap to the
    opposite end of the animation.

    eg. ANLinearCycle1D propName rotations forwardTime 1.0 delayTime1 0.5 backwardTime 0.0 delayTime2 1.0 amplitude 2.0 phase 0.5
        ANLinearCycle2D propName radii forwardTime 1.0 2.0 delayTime1 0.5 0.25 backwardTime 0.0 0.15 delayTime2 1.0 2.0 amplitude 2.0 2.0 phase 0.5 1.5
        ANLinearCycle3D propName translation forwardTime 1.0 1.0 0.5 delayTime1 0.5 0.0 0.5 backwardTime 0.0 5.0 1.25 delayTime2 1.0 1.0 1.0 amplitude 2.0 2.1 2.2 phase 0.5 0.5 0.0

    Parameter            Type   Default     Description
    forwardTime          varies 1.0         The time to animate the forward
                                            phase
    delayTime1           varies 1.0         The time to hold the value steady at
                                            the end of the forward phase
    backwardTime         varies 1.0         The time to animate the backward
                                            phase
    delayTime2           varies 1.0         The time to hold the value steady at
                                            the end of the backward phase
    amplitude            varies 1.0         The maximum distance (both positive
                                            and negative) from the starting
                                            value
    phase                varies 0.0         The amount of time into the
                                            animation to start


2.6  LIGHT SOURCES
--------------------------------------------------------------------------------

LightSource
    A light source to light the scene. These are not a part of the stack and can
    be defined at any point in the .scn file except for the first line, though
    it is best to define them all together at the end of the file. At this time,
    light sources cannot be animated.

    A light's power attenuates with distance [luminance / (distance *
    distance)]. A decent illumination may be 150 at a distance of 10 meters. If
    you double the distance, multiply the power by 4. Lower ambient power values
    (perhaps 0.1-0.2) work well for light sources close to the objects, while a
    higher value (perhaps 0.4-0.5) works well for larger, more distant lights
    such as for an outdoor scene.

    eg. LightSource position 2.0 5.0 -3.0 luminance 150.0 ambientPower 0.2 color 1.0 1.0 1.0

    Parameter            Type   Default     Description
    position             vec3   5 5 -3      The absolute position of the light
                                            source
    luminance            float  100.0       The power of the light directly at
                                            its source. Attenuates by 1.0 /
                                            (distance * distance)
    ambientPower         float  0.2         The amount of the light that still
                                            affects the surface even if it is
                                            shadowed or facing away (0.0-1.0)
    color                vec3   1 1 1       The color of the light


2.7  stepBack
--------------------------------------------------------------------------------

stepBack
    Removes the top object from the stack and returns to the previous level.
    Note: it is not required to stepBack to the base level at the end of the
    file, though it is recommended for consistency and to facilitate any future
    edits to the .scn file. A stepBack that moves beyond the base layer will be
    ignored, but should be avoided for clarity.

    eg. stepBack

    No parameters.
